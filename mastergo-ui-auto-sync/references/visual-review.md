# 参考拆解与生成后视觉打磨

## 参考转成设计规则

用户提供的参考优先，先实际查看图片。记录原图尺寸与目标宽度，按目标宽度估算比例，区分直接观察、尺寸估计和适配提案。必要时补查特定模块。

输出简短规则表，每行包含“参考区域、观察细节、目标规则、应用模块、库能力或待核验项”。覆盖首屏头部高度与颜色面积、内容边距、主次卡片比例、字体层级与数字基线、内外间距、圆角与阴影、图标材质与光线、状态色和底部操作。位图估值不冒充设计源文件的准确参数。

把参考规则映射到实际需求，说明哪个模块承接主视觉、哪个入口获得强调，保持业务优先级和字段完整。图标与素材需形成一致风格，真实数据、标题和按钮保持可编辑。记录与团队库的冲突及可行适配。多页任务可先用代表页或关键首屏验证，再扩展已确认规则；依用户交付节奏执行。

## 业务保护

生成前记录字段、数值与精度、单位、文案、状态条件、按钮行为、跳转目标和权限范围。视觉迭代只调整字号字重、行高、间距对齐、颜色、圆角阴影、图标素材及容器的视觉布局。修改后逐项核对业务记录。影响信息顺序或业务优先级的调整需有需求依据。

## Impeccable 方法的 MasterGo 适配

参考来源 https://github.com/pbakaus/impeccable 。此处为独立总结的审查方法，不依赖安装该项目。未来明确调用已安装 Impeccable 时读取其当时规则。截图无法证明代码性能、DOM语义或真实交互，相关项标为未验证。

1. critique。对照已确认参考与规则表，检查首屏焦点、主次比例、留白节奏、信息密度和素材一致性。指出可见的同质卡片、无业务依据的装饰、弱层级、重复图形等问题，并解释其影响；避免用笼统“AI感”作为结论。
2. audit。检查实际画布边界、裁切溢出、对齐、文字可读性、颜色对比、组件实例表现、跨页一致性与状态辨识。问题记录所在节点或区域、截图证据、严重程度及最小修改建议。先修影响阅读的问题，再处理视觉细节。
3. polish。在已授权且工具允许的范围内，针对优先问题局部调整。微调字重、行高、基线、卡片内边距、图标比例、边框与阴影。保留确认过的品牌表达，依据具体画面判断渐变和卡片的使用。
4. 复看。用修改后的同区域截图对比参考和修改前结果，核对业务保护项。停止于已确认规则落实、关键可见问题消除。仍需新风格决策或素材时记录待定项。用户跳过复核时记录未验收。

## 最多三轮自动检查与修复

用户采用本技能生成页面时，默认将生成后的视觉审查和修复作为交付步骤。每张页面最多三轮，问题提前解决即可结束，用户另行要求跳过时遵从。默认每轮实际截图检查、按证据最小修改、等待更新结果可读取、截图核验。用户明确要求统一末次核验时，前两轮可用已有截图和最新节点结构检查，第三轮结束后读取新截图，不能把结构检查计作视觉核验。上一轮修复后的截图可作为下一轮起点，禁止读取到旧结果后重复提交。

- 第一轮优先处理边界、裁切、溢出、文字可读性和对齐。
- 第二轮对照参考规则，打磨焦点、比例、卡片层次、图标一致性和色彩。
- 第三轮核对细节及跨页一致性，并核查所有业务保护项。

轮次是优先侧重，发现高优先级问题时及时处理。每轮记录截图对应的更新、发现问题、修改节点和复核结果。第三轮修改后仍需有实际截图确认结果，不计为第四轮修复。达到三轮仍有问题时报告剩余问题及证据，不继续扩大范围或声称通过。工具失败、渲染未知或拿不到新截图时记录暂停点，不虚记检查轮数。

## 工具与授权

生成后主动安排本阶段，但遵守实时 MasterGo 协议。已有自动修复授权时，工具允许的检查和视觉修复直接执行，不重复索取同一授权。工具要求提交后停下、另行确认 QA 或修复时，按其精确会话处理，并说明实际约束。不得把本文件当作绕过工具门禁的依据。只有得到实际截图才能报告视觉审查完成。

交付记录已修问题、仍存限制、前后截图证据和业务核对结果。项目档案保存参考规则、审查问题、修改节点及下一步。
