# 设计执行与恢复

## 视觉规则落实

从已确认参考选出最影响观感的三到五条规则，逐条记录目标值或比例、对应模块、实现方式与验收证据。优先覆盖色彩区域边界、主次面积、首屏焦点、字体层级和留白节奏。图标按业务含义选取并记录来源、名称、风格和大小。参考采用渐变或卡片有明确依据时保留其表达。

先完成代表页或关键首屏，再依据实际截图确认规则是否落实；用户要求直接多页时遵从。扩展页面复用已确认的数值规则和布局结构，逐页按内容适配。仅增加配色、圆角或装饰不算规则落实。提交前逐条记录已实现、待核验和能力限制。

## 组件能力与收益

读取所选库后建立简短能力表，记录候选组件、实际读取的 props/slots/text/尺寸能力、业务适配情况与采用方式。采用方式区分真实实例、仅变量、定制图层。空 props 表示当前快照没有暴露字段，不能推断库本身没有该能力。允许时针对确切候选核实，禁止反复全库刷新或遍历未选库。

原样实例符合业务即可复用。字段、状态或尺寸无法表达时记录缺口，按实时工具允许的方式定制；若工具禁止拆解，保留阻碍并说明。交付明确实际复用范围，不能把变量引用描述成组件实例复用。图标库与组件库分别记录，沿用用户已确认来源。

## 结构检查

生成与修复均按完整节点或模块边界修改，禁止通过字符串截断、跨容器全局替换拼接页面。先列出根节点、页头、内容、列表、卡片、操作区的父子关系，确保闭合。渐变绑定明确区域，列表作为内容区的子节点，外边距由内容容器承载。

核查固定宽度、内边距、间隙和子项合计，正文允许合理换行。进度、比例等视觉长度统一从业务数据与实际可用宽度推导，相同数据采用相同规则；不得逐条硬改不同长度。区分完整长画板与固定高度视口，说明底栏布局类型，避免任意固定根高度留下空白或裁切。

修复前读当前快照，保留未改节点ID、属性及素材引用。更新优先定位最小完整模块；对比业务内容及未修改区域。工具要求保留旧样式时照其协议执行。

## 提交台账与恢复

每张画板独立记录目标文件、页面、根节点、请求ID、QA会话、已授权操作、提交状态、证据时间、完成轮次与下一步。逐页维护有效会话，避免后页生成使前页会话失效；若工具仅允许单个待处理会话，先处理再继续，说明真实工具约束。

把“准备、已受理、渲染已证实、已检查、待修复、修复待复核”分开。更新受理后仅按允许的完成信号继续，工具要求本轮停止时保存恢复点。已有授权不重复询问，工具强制问询单独说明。

节点不存在时先核对文件与页面、读取用户指定的准确链接或当前选择；在有新定位证据时重试一次。批量读取失败后可单独核对各节点。不能从旧截图推断节点仍有效；无法恢复时仅索取缺失的定位或连接信息，禁止重建副本掩盖失败。
