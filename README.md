# MasterGo UI Auto Sync

当前版本为 v1.1.1。

将需求、原型和视觉参考转为 MasterGo 可编辑页面，支持从用户验收的设计稿扩展页面，并执行视觉审计与局部打磨。

## 工作模式

1. 分析模块、字段、数值、状态、操作与待定业务规则。
2. 优先拆解用户参考图。需要检索时按美叶、花瓣、站酷寻找参考，按视觉问题组织中英文关键词。
3. 将参考比例、字体、间距、色彩、卡片、图标与阴影映射到业务模块。
4. 确认风格和用库，核验实际组件能力。
5. 按确认尺寸逐页新增或修改设计。
6. 依据截图和结构证据，最多三轮视觉打磨，核对业务内容后交付。

已有验收样板时，读取最新节点和截图，提取实际规范并按新业务适配。人工修改后的样板优先于旧参考。

## Apple Design 基础要求

页面生成及修改采用 apple-design 框架，检查适用平台的可访问性、导航、安全区域、文字层级和状态表达，再结合参考与团队库设计。生成后先检查基础要求，再执行视觉打磨。用户指定图标库继续沿用。静态稿无法验证的交互和辅助技术能力会明确标记。

## 安装与依赖

将仓库中的 mastergo-ui-auto-sync 文件夹复制到 ~/.codex/skills/，在 Codex 中确认技能可见。
同时安装 [dickwu/apple-design-skill](https://github.com/dickwu/apple-design-skill)，使其入口位于 ~/.codex/skills/apple-design-skill/SKILL.md。该依赖提供 Apple Design 审查框架与参考资料。
运行环境需要可连接目标文件的 MasterGo MCP。截图、节点读取、编辑和组件读取能力由实际工具提供。
外部参考研究需要网页或浏览器访问能力。用户指定的图标库、字体和素材需要可核验来源。
更新现有安装前自行保留本地定制内容，再复制新版技能目录。

## 使用方法

首次设计提供需求来源、参考、目标链接、尺寸与页面倾向。先分析再确认风格，之后生成。
多页项目建议先验收一张样板，手动调整后发送最新链接，让后续页面继承实际设计规范。
视觉修复保留业务字段、数值、文案、状态规则、操作与跳转。交付区分受理、渲染和验收状态。

## 提示词模板

### 根据需求和参考设计

```text
使用 $mastergo-ui-auto-sync。
需求来源：[附件或文字]
UI参考：[参考图或链接；没有则请寻找]
MasterGo目标：[链接]
页面尺寸：[393px宽]
页面倾向：[偏运营或偏数据展示]
组件库：[指定库名或请查询推荐]
图标库：[指定来源，如官方IconPark]
画板处理：[新增保留旧版或修改指定画板]

先分析需求并拆解参考细节，输出设计规则与业务模块映射。
等我确认风格和用库后生成，先做一张样板页。
生成后最多三轮视觉打磨，保留业务内容与逻辑。
核验方式：[逐轮截图或三轮结束后统一截图]
允许直接执行截图检查与视觉修复，遵守实际工具协议。
链接不可读时说明具体阻碍，业务待定项明确标记。
```

### 按已验收设计稿扩展

```text
使用 $mastergo-ui-auto-sync。
以我手动调整并验收的样板为准：[链接]。
读取最新节点和截图，提取实际规范。
新页面需求：[附件或文字]
目标位置：[链接]，宽度[393px]。
沿用已确认组件库和图标来源，新增画板保留旧版。
按内容适配布局，生成后对照样板检查并进行视觉修复。
```

### 只做视觉打磨

```text
使用 $mastergo-ui-auto-sync。
目标画板：[链接]，已确认参考：[图片或样板链接]。
执行最多三轮视觉审计与修复，重点处理[具体问题]。
允许直接截图、局部修补，三轮结束后统一核验。
保留业务字段、数值、文案、状态、操作和跳转。
记录各轮修改、真实核验状态及剩余问题。
```

## 能力与验证范围

技能引入了 Impeccable 的审查方法总结，运行无需安装 Impeccable。
真实组件复用取决于工具读取到的字段，交付会区分实例、变量与定制图层。
MasterGo 强制确认、提交后停止与会话有效期可能使流程跨轮恢复。
新增规则尚需持续通过完整项目验证，已受理不能作为视觉验收结论。

完整规则见 [SKILL.md](mastergo-ui-auto-sync/SKILL.md)，版本说明见 [RELEASE_NOTES.md](RELEASE_NOTES.md)。
